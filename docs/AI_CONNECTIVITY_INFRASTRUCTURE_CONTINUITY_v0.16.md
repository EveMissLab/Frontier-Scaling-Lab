## 0. 新增此軌道的真正目的

AI 的文明能力不能只由模型 benchmark、運算速度、參數量、價格或互動功能衡量。即使 AI 能在本地或雲端完成任務，仍需回答：

> 在世界不同地點、不同通訊條件和部分基礎設施故障時，AI 是否還能取得必要訊息、與其他系統溝通、保存身份／狀態、履行授權任務、以合法方式恢復服務，並在失聯時維持必要的本地安全與自主？

這裡研究**AI 連線能力的建設與運作條件**。它既不是 AI 具備主觀意識或人格的證據，也不是把既有工具稱為「一個智慧體」的本體判斷。其觀測範圍包含具身機器人、跨雲工作 Agent、不同服務商協作、AI↔AI 通訊、緊急通訊、分散式知識與任務交接。人類在治理與高風險任務中仍保有合法停止、授權和最終裁決權。

**網速不是最高層指標。** 下載 1 Gbps 可能無法存取所需模型；而只有幾 kbps 的備援網路也可能支援緊急求救、關鍵命令和狀態回傳。反之，低速安全消息不能假稱能夠滿足多模態大模型的高吞吐需求。

## 1. 五層「能連線」的區分

1. **物理／鏈路層**：終端、衛星、行動基地台、光纖或海纜是否真的可接入；其供電、天候、視距及容量是否足夠。
2. **傳輸／路由層**：DNS、BGP、IP、TCP／QUIC、TLS、對等互連與 CDN 是否能導向目標服務。
3. **服務／授權層**：Cloud/API 的帳號、地域、政策、配額及防火牆是否允許請求；403、401 或 429 不應直接當成實體網路中斷。
4. **語義／狀態協作層**：不同 AI 或不同裝置是否真正能交換必要訊息、回執、長期任務狀態、版本與因果順序；訊息送達不代表任務完成。
5. **真實任務／文明層**：機器人、研究系統、企業或公共服務是否在故障前後完成有用、可驗收且安全的最終成果。

各層分開量測、保持時間戳及來源，不能把一層的成功直接上推到另一層。

### 1.1 聯邦式具身智能的分層責任

可以研究一個四層候選體系：本地具身體（即時控制、必要記憶、緊急停止）、區域邊緣智能（協作、低延遲推理）、都市／跨區網路（群體協調）、遠端超算或雲端 AI（高負載科研與全域規劃）。

這只是**分層功能參考**，不是所有未來 AI 的唯一架構。尤其不能用衛星網路的往返時間作為生命攸關避障的唯一控制迴路；高風險動作要有本地、獨立的安全界線，且在失聯、失電或狀態失真時能安全降級。

### 1.2 Connectivity + Isolation + Verification + Reversibility

- **Connectivity**：能否在指定任務條件下接上必要的服務或代理，而非僅看到訊號。
- **Isolation**：跨網路互通不等於共享身份、記憶、API Key 或執行權限。
- **Verification**：有可重播的交付、狀態、版本、外部執行與安全收據。
- **Reversibility**：撤權、停止、重連、回滾與故障交接不得失去責任與因果界線。

這四項並不是四個可以相加的「AI 智力點數」，而是使跨網路 AI 協作可信的不同必要條件。

## 2. 十四個研究維度、七十個細項

機讀目錄：`data/ai_connectivity_capability_catalog_v0.16.json`。

| 代碼 | 研究維度 | 關鍵問題 |
|---|---|---|
| COV | 覆蓋與真正接入 | 服務是否實際可用、合法且可提供最低必要能力？ |
| TOP | 媒介與共因故障拓撲 | 兩條備援是否真的有不同故障依賴？ |

## 3. 衛星並非海底電纜的全域等價替代品

國際電信聯盟（ITU）將海纜視為全球跨境資料交換的骨幹，並將衛星定位為擴大地理覆蓋和應急韌性的互補系統。

- 海纜與陸地光纖：高容量的主要骨幹，可能受斷纜、登陸站、地震、錨損與維修周期影響。
- 地面行動通訊：可支援大量移動終端與近距離連線，但共用基地台、回程骨幹及電力。
- 衛星（LEO／MEO／GEO）：能支援無線覆蓋和部分路由備援，但仍涉及終端供電、可見性、衛星地面閘道、互聯網出口和服務商政策。
- 星間雷射：可在衛星之間轉送資訊、繞過部分地面節點，但不能保證任何特定地面 API／模型或使用者授權必然可存取。
- 未來在軌算力：與衛星通訊是不同設備、能源、散熱、硬體與驗收問題；小型在軌模型示範不等於大型軌道訓練中心已成經濟上可行方案。

研究必須追蹤**共同失效域**：例如有光纖和衛星兩種接入方式，卻共用一個供電來源、ISP 上游、DNS、雲端區域、API 帳號或地面閘道，則「兩條路」可能無法承受同一事故。

資料來源（2026-11-08 檢索）：
- ITU 海纜韌性：https://www.itu.int/en/mediacentre/backgrounders/Pages/submarine-cable-resilience.aspx
- ITU 全球通訊韌性：https://wtpf.itu.int/2026/about/thematic-areas/resilience-of-telecommunication-icts/
- Starlink 原廠衛星／光學星間鏈路描述：https://starlink.com/technology
- 2025 年學術研究對 Starlink 地面出口與 PoP 依賴的分析：https://doi.org/10.1145/3715335.3735467

原廠產品頁只證明廠商公開如何描述設計，不直接驗證所有地區或任務中的可用率。

## 4. 與「未來網路主要由 AI 使用」的研究接口

v0.15 記錄了當時產業人物如何談論 AI 網路流量、Agent 協作、衛星和軌道算力；v0.16 進一步把主張轉成可測的基礎設施條件。

必須固定分母與樣本母體，分開：HTTP 請求、傳輸位元組、端到端任務會話、真正自主 Agent 互動、一般 Bot、資料中心內部流量、可驗收成果和最終付費需求。即使 AI↔AI 請求遠多於人類請求，也不能單由流量推論有同等文明價值、獨立購買力或法律自主權。

## 5. 對照實驗：設計重點是故障，而不是最漂亮的速度結果

### A. 國際海纜受損

前置：正常光纖主路徑及合法衛星備援。實驗將主路徑標成不可用，但不捏造真的實體海纜故障。要記錄備援是否能完成**相同任務**、有沒有共用地面出口、切換耗時和額外成本。系統進入另一條網路，不保證所有雲端服務還能使用。

### B. 連上網卻得到 403

主鏈路與路由可用，但模型 API、平台代理或防火牆拒絕請求。此時根因是服務存取政策、身份或授權，不能把它寫成網路不可達，也不應建議繞過服務商的安全或存取規則。

### C. 衛星與地面服務同時無法使用

因共用電力、區域網路或雲端服務失效而無法取得遠端支援。具身體應在**本地可驗證的安全邊界**內繼續必要工作；超出邊界則安全停止。離線等待時間不能冒充實際完成任務的自主時長。

### D. 重連後的訊息、授權與記憶衝突

讓兩個 Agent 在斷線期間更新工作狀態，重新連線後驗證：來源是否可信、事件是否重複、已撤權工具是否仍被調用、先後時序是否合理、何時升級給人類。尤其不能將收到訊息、採納計畫與真正執行外部動作混成一個狀態。

以上四例於本版的資料檔中均為 **SYNTHETIC（合成測試）**；不提供現實的衛星覆蓋率、故障發生率、網速或 AI 成功率。

## 6. 觀測資料的必要紀律

每一個觀測事件至少記錄：

- 指標 ID、任務 ID、真實系統與堆疊指紋、場所／範圍、測試日期和截點；
- 主要／備援媒介、共同依賴未知或已核對、故障注入／真實事故分類；
- 鏈路是否可用、服務是否可用、授權是否有效、AI 任務是否完成、具身安全是否維持；
- 有沒有人工直接補工、是否為真實測試／廠商宣稱／純合成；
- RTO／RPO／延遲及其單位（未知為 null，不能偷偷用零）；
- 外部可回溯收據、原始來源發布日、FSL 登錄日與後續修訂關係。

本版不提供全球「AI 連線能力指數」，更不將 Starlink 速度直接加成為 AI 認知能力。每項結果須能在指定測量母體與時間窗口內成立。

## 7. 與前版的結構關係

- **v0.13 GICCF**：保留智慧體在文明活動的能力集合；網路是活動能否部署的限制，不是可以代替 G1–G4／E1 驗收的分數。
- **v0.14 無 AI 反事實研究**：人類與 AI 的比較可納入同時代通信科技與建設條件；不得把未來衛星容量虛構成已存在。
- **v0.15 公開言論與演化**：產業預測只作歷史候選假說。未來需要以實際建設、路由、故障、費用和成果驗證。
- **SAS-01 系統性支持域**：網路能力是能源、算力、硬體、物流和物理產能支撐系統的一部分；網路升級本身不等於整體正向再生閉環。

## 8. 驗證方式

初版提供只讀目錄／案例稽核以及合成失效資料：

```bash
python -m fsl_connectivity.cli catalog
python -m fsl_connectivity.cli audit --file tests/fixtures/connectivity_synthetic_v0.16.json --as-of 2026-11-08
python -m unittest discover -s tests -q
```

**研究結論：AI 未來能否在世界中持續完成文明活動，不能只問它能算什麼，也要問它從哪裡取得消息、如何連到其他智慧體、斷線後能做什麼，以及它的行動權與安全如何在網路故障中仍保持有效。**
